# profiles/plsql.md: PL/SQL Dialect Profile (Oracle Database)

Active profile for repositories whose primary database is Oracle. Load this
file when `RULES.md` declares `Domain: profiles/plsql.md`.

This profile is normative. It states what agents MUST and MUST NOT do. For
implementation patterns, load
[`skills/database-access.md`](../skills/database-access.md); this file does not
restate its recipes.

Stacks on top of [`profiles/python.md`](python.md) and any active framework
profile, all of which remain in force. The framework profiles already mandate
SQLAlchemy 2.x typed models, which abstracts most of what follows. The rules
here bind the places dialect actually leaks through: raw SQL, DDL, connection
strings, PL/SQL blocks, and error handling.

Oracle diverges from the other two dialects more sharply than they diverge from
each other. Three behaviors have no counterpart elsewhere and are called out
below: uppercase identifier folding, `''` being `NULL`, and DDL committing the
current transaction implicitly.

---

## Connectivity

**Rule:** No Oracle driver is currently authorized. `python-oracledb` and
`cx_Oracle` are absent from
[`skills/approved-packages.md`](../skills/approved-packages.md), the
authoritative list for
[RULES.md §5](../RULES.md#5-third-party-library-authorization-core). Adding one
requires the §5 approval process, and then the 72-hour cooling period recorded
in the project's `authorized_libraries.md`, before any connection code is
committed.

Once a driver is authorized, these requirements apply:

| Concern | Requirement |
|---|---|
| DSN | From a `DATABASE_URL` environment variable, never a literal |
| Client mode | Thin mode where the feature set allows, so no Instant Client is required on the host |
| TLS | Required for any non-local host |
| Pooling | A session pool with explicit min and max; never a connection per request |
| Service name | Connect by service name, never by SID |

Extends [RULES.md §8](../RULES.md#8-security-and-secrets-core).

### Prohibited

```python
create_engine("oracle+oracledb://app:hunter2@prod:1521/?service_name=APP")  # NEVER
logger.info("connecting to %s", settings.database_url)                      # NEVER
```

Oracle session establishment is expensive relative to Postgres and SQL Server,
so an unpooled connection per request will breach the §14 latency target on its
own.

## Identifiers and Types

**Rule:** Identifiers MUST be unquoted and written in lower_snake_case in source
code. Quoted identifiers are prohibited in new objects. Column types MUST be
chosen from the table below.

Unquoted identifiers fold to **UPPERCASE**, the opposite of PostgreSQL. An
object created as `"order_id"` can then only ever be referenced as
`"order_id"`, in every tool, forever. Create `order_id` unquoted and let it
fold; refer to it in whatever case is convenient.

### Required type choices

| Use | Use this | Not this | Why |
|---|---|---|---|
| Text | `VARCHAR2(n CHAR)` | `VARCHAR`, `CHAR` | `VARCHAR` is reserved for future redefinition; `CHAR` blank-pads |
| Large text | `CLOB` | `LONG` | `LONG` is deprecated and limited to one per table |
| Timestamp | `TIMESTAMP WITH TIME ZONE` | `DATE` | Oracle's `DATE` includes a time but no fractional seconds and no offset |
| Money and exact decimals | `NUMBER(p,s)` | `BINARY_DOUBLE`, `FLOAT` | Binary floats cannot represent decimal cents |
| Surrogate key | `GENERATED BY DEFAULT AS IDENTITY` (12c+) | A sequence plus a `BEFORE INSERT` trigger | The trigger pattern is legacy and hides the assignment |
| Boolean | `NUMBER(1)` with a `CHECK (col IN (0,1))` | A `CHAR(1) 'Y'/'N'` convention | SQL-level `BOOLEAN` does not exist as a column type before 23c |

### The empty string trap

In Oracle, `''` is `NULL`. There is no distinction between an empty string and
a missing value.

```sql
INSERT INTO t (name) VALUES ('');   -- stores NULL
SELECT * FROM t WHERE name = '';    -- returns nothing, ever
```

Any code ported from PostgreSQL or SQL Server that distinguishes `''` from
`NULL` MUST be reviewed against this rule. A `NOT NULL` column will reject an
empty string, which is frequently the first symptom.

## Parameterization

**Rule:** Every value interpolated into SQL MUST be a bind variable. This is a
correctness and performance requirement in Oracle, not only a security one.

Extends [RULES.md §8](../RULES.md#8-security-and-secrets-core) and
[RULES.md §14](../RULES.md#14-performance-standards-langpython-configurable).

| Layer | Placeholder |
|---|---|
| SQLAlchemy `text()` | `:name` |
| `python-oracledb` directly | `:name` named binds |
| PL/SQL block | `:name` for host variables |

### Prohibited

```python
cursor.execute(f"SELECT * FROM users WHERE email = '{email}'")   # NEVER
```

```sql
-- NEVER: concatenated dynamic SQL
EXECUTE IMMEDIATE 'SELECT ... WHERE email = ''' || p_email || '''';

-- Correct
EXECUTE IMMEDIATE 'SELECT ... WHERE email = :e' INTO l_row USING p_email;
```

### Rationale

Beyond injection, every distinct literal produces a distinct SQL text, which
forces a hard parse and a new shared pool entry. A loop that concatenates
literals will flood the shared pool, spike library cache latch contention, and
degrade the entire instance, including sessions belonging to other
applications. Bind variables are the single most consequential Oracle
performance rule.

## Query Constructs

**Rule:** Every query that returns a set MUST be bounded, and every paginated
query MUST have an `ORDER BY`.

### Pagination

```sql
SELECT id, email FROM users
ORDER BY id
OFFSET :offset ROWS FETCH NEXT :limit ROWS ONLY;
```

`OFFSET ... FETCH` requires 12c or later. On older versions, the idiom is a
nested `ROWNUM` subquery:

```sql
SELECT * FROM (
    SELECT t.*, ROWNUM AS rn FROM (
        SELECT id, email FROM users ORDER BY id
    ) t WHERE ROWNUM <= :max_row
) WHERE rn > :offset;
```

The double nesting is required: `ROWNUM` is assigned before `ORDER BY` is
applied, so `WHERE ROWNUM <= n` against an unordered inner query returns an
arbitrary set. Note that `LIMIT` does not exist in Oracle; any query using it
came from another dialect.

For deep paging, use keyset pagination.

### Upsert

`MERGE` is the correct and race-safe idiom on Oracle, unlike on SQL Server:

```sql
MERGE INTO counters c
USING (SELECT :key AS k, :value AS v FROM dual) s
   ON (c.key = s.k)
 WHEN MATCHED THEN UPDATE SET c.value = s.v
 WHEN NOT MATCHED THEN INSERT (key, value) VALUES (s.k, s.v);
```

A unique constraint on the join column is still required.

### NULL ordering

Oracle sorts `NULL` last in `ASC` and first in `DESC`, matching PostgreSQL and
opposing SQL Server. `NULLS FIRST` and `NULLS LAST` are supported; state them
explicitly wherever the result is compared across dialects.

### Prohibited

```sql
SELECT * FROM events;                       -- NEVER: unbounded in a request path
SELECT ... WHERE ROWNUM <= 100 ORDER BY id; -- NEVER: ROWNUM applied before ORDER BY
```

## Transactions and DDL

**Rule:** Every write path MUST have an explicit `COMMIT` or `ROLLBACK`. DDL
MUST NOT be issued inside an open application transaction.

### DDL commits implicitly

Oracle issues an implicit `COMMIT` immediately before and after every DDL
statement. A DDL statement in the middle of a transaction therefore commits all
preceding uncommitted work, silently and irreversibly.

```sql
-- NEVER: the CREATE INDEX commits the UPDATE, defeating the ROLLBACK
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
CREATE INDEX ix_accounts_balance ON accounts(balance);
ROLLBACK;   -- rolls back nothing
```

This is the sharpest divergence from PostgreSQL and SQL Server, both of which
have transactional DDL. Migrations MUST assume no rollback is available and
MUST be written so that a failure at any statement leaves a recoverable state.

### Mandatory practices

| Concern | Requirement |
|---|---|
| Isolation | Default `READ COMMITTED` is acceptable; `SERIALIZABLE` where a read informs a write |
| Autocommit | Disabled. Commit explicitly at the service-layer boundary |
| Long operations | `SELECT ... FOR UPDATE` with a defined lock scope; never lock a whole table |
| Backfills | Batched with a commit per batch, sized to avoid ORA-01555 |
| Migrations | Through `alembic`, per the active framework profile, one DDL statement per revision |

### Prohibited

- Do NOT hold a transaction open across a network call to another service.
- Do NOT rely on a rollback undoing a migration. Write a compensating
  migration instead.
- Do NOT issue DDL from application code at runtime.

## Error Handling and Testing

**Rule:** PL/SQL exception handlers MUST name the exceptions they handle.
`WHEN OTHERS THEN NULL` is prohibited, as is any `WHEN OTHERS` handler that
does not re-raise. This is the PL/SQL form of the bare `except` prohibition in
[RULES.md §9](../RULES.md#9-error-handling-langpython).

```sql
EXCEPTION
    WHEN DUP_VAL_ON_INDEX THEN
        log_pkg.warn('duplicate key on ' || p_key);
        RAISE;
    WHEN OTHERS THEN
        log_pkg.error(SQLCODE || ': ' || SQLERRM);
        RAISE;                      -- always re-raise
```

```sql
-- NEVER: swallows every error, including ones that lose data
EXCEPTION WHEN OTHERS THEN NULL;
```

### Error code mapping

| Error | Meaning | Correct handling |
|---|---|---|
| `ORA-00001` | Unique constraint violated | Map to a 409 or a domain "already exists" error |
| `ORA-02291` | Parent key not found | Map to a 422, not a 500 |
| `ORA-00060` | Deadlock detected | Retry with backoff |
| `ORA-01555` | Snapshot too old | Batch the operation smaller; do not retry unchanged |
| `ORA-04068` | Package state discarded | Reconnect, then retry once |

Match on error code, never on message text.

### Testing

Do NOT substitute SQLite or PostgreSQL for Oracle in tests. Identifier folding,
`''` as `NULL`, DDL commit behavior, and sequence semantics all differ, so a
suite passing elsewhere proves nothing. Run a real Oracle instance (XE or a
container image) and roll back a transaction per test.
