Commit and ship the current session's work as a PR. Complete all steps in order.

## Step 1 — Attribution scan

Before committing, scan staged changes for any agent attribution:

```bash
git diff --cached | grep -inE "claude|anthropic|co-authored|generated with|ai-generated|chatgpt|copilot"
```

If anything matches, remove it before proceeding. Per `issue-protocol.md` (Authorship Policy):
- No `Co-Authored-By:` lines in commits
- No AI-generated footers in PR bodies
- No agent attribution in filenames, function names, comments, or references
- The human user owns accountability for all committed code

## Step 2 — Commit

Write a plain summary line (what changed, not "Generated by..."). List closed issues **one per line**, not comma-separated — GitHub's closing-keyword parser has been observed to only auto-close the first issue in a comma-separated list on merge:

```bash
git commit -m "$(cat <<'EOF'
<plain summary of what was added/changed>

Closes #<N>
Closes #<N>
Closes #<N>
EOF
)"
```

## Step 3 — Push and open PR

```bash
git push -u origin <branch>
gh pr create --title "<title>" --body "$(cat <<'EOF'
Closes #<N>
Closes #<N>

- <file> — <one-line summary>
- <file> — <one-line summary>
EOF
)"
```

Do not append a "Generated with Claude Code" or similar footer to the PR body.

## Step 4 — Verify

```bash
git log -1 --format=full | grep -inE "claude|anthropic|co-authored|generated|ai-generated"
gh pr view <number> --json title,body,author
```

Expect no matches from the grep, and `author.login` to be the human user, not a bot.

## Step 5 — Post-merge issue check (if PR is already merged)

Auto-close via `Closes #N` isn't always reliable across multiple issues. After merge, confirm every referenced issue actually closed:

```bash
gh issue list --state all --json number,state,title -q '.[] | select(.number==<N> or .number==<N>)'
```

Manually close any that didn't auto-close:

```bash
gh issue close <N> --comment "Closed via #<PR-number> (merged)."
```
